# Котолов

Браузерная игра на JavaScript и Canvas. Использует фон и персонажей из этого репозитория; подготовленные прозрачные спрайты находятся в `assets`.

## Запуск

```sh
npm install
npm run dev
```

## Управление

- **← / →** — двигать ловца.
- **Пробел / Escape** — пауза и продолжение.
- **Enter / Пробел** — начать новую игру на стартовом экране.
- На телефоне — экранные стрелки.

За каждого пойманного кота начисляется 10 очков. Три пропущенных кота завершают игру. Каждые 20 секунд повышается сложность. Рекорд сохраняется локально в браузере. Звук включается кнопкой в шапке.

## Проверки и сборка

```sh
npm test
npm run build
npm run preview
```

Статическую сборку из `dist` можно разместить на любом HTTP-хостинге.

## Анимация котов

Из шести исходных `cats/cat*_sprite-list.png` вырезаны 39 кадров
(7, 5, 5, 10, 5 и 7). Отдельные прозрачные PNG лежат в
`assets/animations/cat1/` … `cat6/`; горизонтальные атласы
`assets/animations/cat1.png` … `cat6.png` сохранены для удобства.
Игра загружает **все 39 отдельных кадров** через `frames.js` перед стартом
и выбирает новое изображение каждые 125 мс игрового времени.
Все кадры имеют размер 192×192. Размер персонажа нормализован одним
масштабом на весь набор, чтобы кот не менял размер между позами.

Анимация проигрывается вперёд-назад со скоростью 8 кадров в секунду.
Каждый кот получает собственную начальную фазу, а пауза останавливает
как падение, так и смену кадров. Анимированы также коты на стартовом экране.

Для повторной нарезки (исходные изображения не изменяются):

```sh
python -m venv .venv
.venv/bin/pip install Pillow
.venv/bin/python scripts/prepare_animation.py
```

Можно нарезать вложения из другой папки: `python scripts/prepare_animation.py --source /путь/к/файлам`.

## Анимация игрока

`man_sprites.png` нарезан на семь прозрачных кадров в
`assets/animations/player/`. У всех одинаковый холст 320×336,
один масштаб и общая точка привязки по поясу — смена поз не двигает туловище.
При движении стрелками проигрываются позы рук (влево — зеркально),
а успешная ловля запускает последовательность из семи поз со скоростью
10 кадров/с. Пауза замораживает и котов, и игрока.

Повторная нарезка: `.venv/bin/python scripts/prepare_player.py`.

### Надёжная загрузка кадров

Генераторы сохраняют PNG и встраивают их точные копии в `frames.js` как
`data:image/png;base64,…`. Во время запуска кадры не скачиваются отдельными
HTTP-запросами: нет зависимости от путей к 46 PNG, кеша старых файлов и
настроек статического хостинга для спрайтов. Модуль со спрайтами стал больше,
но все кадры входят в сборку. Фон загружается отдельно.
При ошибке загрузчик показывает имя ресурса и позволяет повторить загрузку.

### Совместимость превью (v1.4.0)

Активная отрисовка использует HTML-изображения в слое `#scene`, а игровой
цикл — таймер. Отображение и движение не зависят от Canvas 2D и
`requestAnimationFrame`. Фон виден сразу как обычный `<img>`.
Маркер версии и загрузки находится под игровым полем.

## Автономное превью v1.5

`npm run build` теперь собирает один `dist/index.html`: CSS, обычный JavaScript,
фон, 39 кадров котов и 7 кадров игрока встроены в документ. Нет загрузки
ES-модулей и дополнительных ресурсов. Файл можно открыть даже без сервера.
`npm run preview -- --port 5173` запускает обычный Node HTTP-сервер на
`0.0.0.0` с gzip, запретом кеширования и без ограничений Host/iframe.

Исходные PNG остаются нетронутыми; компактные WebP-копии находятся в
`assets/embedded.json`. Для их обновления после нарезки кадров:

```sh
.venv/bin/python scripts/prepare_embedded.py
npm run build
```

Проверка автономности входит в `npm test`. Дополнительная браузерная проверка
iframe — `node tests/browser-preview.cjs` (требует Playwright и
`@sparticuz/chromium` с доступными системными библиотеками).
Обычную модульную Vite-сборку при необходимости создаёт `npm run build:modules`.

## Вертикальный формат v1.6

Игровое поле имеет портретное соотношение **9:16** на всех экранах
(540×960 игровых единиц, максимум 480 пикселей по ширине на странице).
Координаты появления котов, скорость движения и линия ловли адаптированы
к вертикальному полю. Счётчики компактно расположены сверху, игрок — внизу;
экранные стрелки доступны и на компьютере, и на телефоне.
